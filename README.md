# VALORANT 내전 파워랭킹 - 다중 디스코드 서버 버전

기존 파워랭킹/팀 배정 기능을 유지하면서 여러 디스코드 서버가 각자 독립된 선수 명단, 통계, 팀 이름, 랭킹을 운영하도록 확장한 Vercel + Supabase 웹앱입니다.

## 중요: 기존 사이트에 업데이트하기
1. 이 프로젝트 파일 전체를 기존 GitHub 저장소 루트에 업로드해 기존 파일을 덮어씁니다.
2. Supabase Dashboard > SQL Editor에서 `server-multi-tenant.sql` 전체를 실행합니다. 기존 테이블/데이터를 삭제하지 않습니다.
3. GitHub에 Commit하면 Vercel이 자동 재배포합니다.
4. Vercel 환경변수 `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `ADMIN_EMAIL`은 기존 값이 유지되어야 합니다.

## 사용법
- 기존 사이트 관리자 계정으로 `관리자 모드` 로그인합니다. 이 계정은 사이트 전체 관리자이며 새 디스코드 서버를 생성할 수 있습니다.
- `+ 서버 생성`에서 서버 이름과 해당 서버의 초기 관리자 비밀번호(8자 이상)를 설정합니다.
- 방문자는 서버 선택 메뉴에서 서버를 바꿔가며 공개 랭킹을 조회할 수 있습니다.
- 해당 서버 관리자는 `서버 관리자 로그인`을 누르고 그 서버의 비밀번호를 입력합니다.
- 서버 관리자는 자기 서버의 선수/팀/카테고리 데이터만 편집할 수 있고 `비밀번호 변경`으로 비밀번호를 변경할 수 있습니다.
- 서버별 비밀번호는 브라우저 코드나 DB에 평문으로 저장되지 않고 PostgreSQL bcrypt 해시로 저장됩니다. 로그인 중 비밀번호는 현재 페이지 메모리에만 유지되며 새로고침하면 다시 입력해야 합니다.

## 보안 모델
- 서버 생성은 Supabase Auth로 로그인한 `admin_users` 사이트 관리자만 가능합니다.
- 서버 데이터 쓰기와 비밀번호 변경은 DB 함수에서 서버 비밀번호를 검증합니다.
- 공개 사용자는 서버 이름 및 랭킹 데이터를 읽을 수 있지만 직접 테이블을 수정할 권한은 없습니다.
- 브라우저에는 Supabase Publishable/anon 키만 사용합니다. `service_role` 또는 Secret key를 프론트엔드에 넣지 마세요.

## 기존 프로젝트 참고
`supabase-schema.sql`은 기존 단일 서버 버전의 초기 스키마입니다. 이미 기존 사이트에서 실행했다면 다시 실행할 필요는 없습니다. 다중 서버 기능을 위해 반드시 `server-multi-tenant.sql`을 추가 실행하세요.


## 업데이트 참고
- 서버 목록에서 프로필 카드를 선택하고 해당 서버 비밀번호를 입력해야 내용을 볼 수 있습니다. 사이트 관리자도 각 서버 비밀번호를 입력해야 해당 서버를 열람/수정할 수 있습니다.
- Supabase SQL Editor에서 이 버전의 `server-multi-tenant.sql` 전체를 다시 실행해 RPC 권한 변경을 적용하세요.
